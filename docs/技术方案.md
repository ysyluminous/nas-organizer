# NAS Organizer 技术方案

## 1. 目标与边界

### 1.1 目标

以 Docker 方式在**任意支持 Docker 的 NAS 或 x86 主机**上运行一个数据治理工具，完成：

1. 对一个或多个共享目录（十万级文件）建立增量索引
2. 按 **归属域 × 文件类型 × 温度层** 三个维度自动分类
3. 检测重复文件并给出清理建议
4. 生成迁移计划，经人工确认后安全执行
5. 热数据自动备份、冷数据索引同步
6. 全程可审计、可回滚、需认证

### 1.2 明确不做

- 不绑定任何 NAS 品牌或盘符路径（路径全部由配置注入）
- 不做文件内容的语义理解（不提取 PDF 正文、不做 OCR）
- 不自动执行任何写操作（所有变更必须人工确认）
- 不修改文件本身（只移动、复制、重命名）
- 不替代 NAS 的 RAID / 快照 / 异地备份

> 作者真实环境的诊断数据与分层方案已独立成文：[案例：绿联 NAS 现状诊断](案例-绿联NAS现状诊断.md)。该案例仅作示例，不是部署前提。

## 2. 部署模型：三类挂载

路径通用化是本方案的基础。容器内的目录职责固定，宿主机路径由用户自定：

| 类别 | 容器内路径 | 权限 | 用途 |
|---|---|---|---|
| A. 扫描源 | `/scan/*` | `:ro` | 扫描、分类、查重——只读 |
| B. 写入目标 | `/write/*` | `:rw` | 执行迁移、热备份——唯一可写业务目录 |
| C. 应用数据 | `/app/config`、`/app/data`、`/app/logs` | 配置 ro / 其余 rw | 规则、索引库、认证密钥、日志 |

```
宿主机共享文件夹 ──:ro──> /scan/media1 ──┐
                                          ├─> Scanner / Classifier / Deduper（无写权限）
                                          │
宿主机归档目录   ──:rw──> /write/target ──┴─> Executor / Backup（仅确认后才写）

宿主机 ./config ──:ro──> /app/config   （规则 YAML）
宿主机 ./data   ──:rw──> /app/data     （SQLite + .auth_secret + auth.yaml）
宿主机 ./logs   ──:rw──> /app/logs     （操作日志）
```

容器进程以 `PUID`/`PGID` 指定的非 root 用户运行，通过 UID/GID 映射获得宿主机目录的相应权限。详见 [挂载配置指南](挂载配置指南.md)。

## 3. 总体架构

```
┌──────────────────────────────────────────────────────────────┐
│                      Docker Container                         │
│                                                               │
│  接入层   A 类只读挂载 /scan/*  +  B 类受控写入 /write/*       │
│     ↓                                                         │
│  安全层   AuthManager：登录认证 / 签名 Token / 限流 / 危险操作确认│
│     ↓                                                         │
│  引擎层   扫描器 → 分类器 → 查重器 → 计划器 → 执行器           │
│     ↓                                                         │
│  索引层   SQLite（文件表 / 标签表 / 计划表 / 操作日志表）      │
│     ↓                                                         │
│  输出层   FastAPI Web 控制台 + CLI + 定时备份任务              │
└──────────────────────────────────────────────────────────────┘
```

### 3.1 模块职责

| 模块 | 文件 | 职责 |
|---|---|---|
| 配置 | `config.py` | 加载 YAML 配置、路径映射、规则开关 |
| 数据库 | `db.py` | SQLite 连接管理、建表、迁移 |
| 模型 | `models.py` | 数据类定义（FileRecord / Plan / Action） |
| **认证** | **`auth.py`** | **PBKDF2 密码哈希、HMAC 签名 Token、登录限流、密钥轮换** |
| 扫描器 | `scanner.py` | 增量遍历、stat 采集、大小/时间过滤 |
| 分类器 | `classifier.py` | 四级判定链、置信度、打标签 |
| 查重器 | `dedupe.py` | 三级哈希漏斗、重复组识别 |
| 计划器 | `planner.py` | 目标路径计算、冲突处理、计划生成 |
| 执行器 | `executor.py` | 复制/校验/删除、回滚、操作日志 |
| 备份 | `backup.py` | rsync 热数据备份、冷数据校验 |
| API | `api.py` | FastAPI 路由、认证中间件、Web 控制台后端 |
| CLI | `cli.py` | argparse 命令行入口 |
| 入口脚本 | `docker/entrypoint.sh` | root 初始化后降权到 PUID/PGID |

## 4. 认证与安全设计

### 4.1 威胁模型与对策

| 风险 | 对策 |
|---|---|
| 任意人打开网页执行移动/删除 | 所有 `/api/*` 强制 Bearer Token，仅登录与状态接口匿名 |
| 默认弱口令被扫爆 | 首次启动生成 20 位随机密码，无硬编码默认密码 |
| 密码库泄露还原明文 | PBKDF2-HMAC-SHA256 + 随机盐 + 21 万次迭代 |
| 抓包重放 / 伪造登录态 | HMAC-SHA256 签名 Token，含 exp、iat、nonce |
| 暴力破解 | 按 IP 计数，超限指数冷却，最长 1 小时 |
| 时序侧信道 | 全程 `hmac.compare_digest` 常量时间比较 |
| 误触危险操作 | execute / rollback 需显式 `confirm=true` + 前端二次确认 |
| XSS / 点击劫持 | 路径 HTML 转义、`X-Frame-Options: DENY`、`nosniff` |
| API 结构探测 | 生产默认关闭 `/docs` 与 `/openapi.json` |

详见 [安全与认证](安全与认证.md)。

### 4.2 Token 流转

```
首次启动 → 生成随机密码 → data/auth.yaml（哈希）+ data/INITIAL_PASSWORD.txt
     ↓ 用户输入密码
POST /api/auth/login → 校验（PBKDF2 + 限流）→ 签发 HMAC Token（8h）
     ↓ 后续每个请求
Authorization: Bearer <token> → 中间件验签 + 查有效期 → 放行
     ↓ 点"执行计划"
confirm=true → 执行器写操作 → op_logs 记录 → 可回滚
     ↓ 修改密码
轮换签名密钥 → 所有旧 Token 立即失效
```

## 5. 分类模型

### 5.1 三个维度（正交）

| 维度 | 取值 | 判定依据 |
|---|---|---|
| 归属域 domain | 个人 / 工作 / 生活 / 资源 | 路径规则、关键词、文件名 |
| 文件类型 ftype | 音乐/视频/图书/文档/图片/软件/压缩包/其他 | 扩展名 + magic bytes |
| 温度层 temp | 热 / 温 / 冷 | mtime/atime、大小、所在卷标记 |

### 5.2 判定优先级（逐级兜底）

```
1. 路径规则     → 命中率约 90%，如 /分享内容/电影/ → 生活·视频
2. 扩展名       → 确定类型，如 .flac → 音乐
3. 文件名关键词 → 确定归属，如 "合同/报表/项目" → 工作
4. 轻量模型     → fastText / TF-IDF，CPU 毫秒级，只处理未命中项
   ├─ 置信度 ≥ 0.8 → 自动归类
   └─ 置信度 < 0.8 → 进人工确认队列
```

模型是兜底而非主力：确定性的分类用规则做，准确率 100%、零延迟。

### 5.3 温度判定规则

```python
if atime_90d or mtime_90d or volume.role == "hot"  -> 热
elif atime_365d or mtime_365d                       -> 温
else                                                -> 冷
# 大文件 > 2GB 且超过 1 年未访问，强制冷
```

## 6. 重复检测（三级漏斗）

针对十万级文件，不能全量哈希：

| 级别 | 方法 | 目的 |
|---|---|---|
| 1 | 按文件大小分组 | 排除 95% 以上文件，只比对同大小的 |
| 2 | 头 64KB + 尾 64KB 哈希 | 快速排除大小相同但内容不同的 |
| 3 | 全量 SHA-256 | 最终确认，只对二级筛后的少数文件做 |

重复组按"保留策略"选出主文件：路径最短 > 层级最浅 > mtime 最新 > 文件名排序。其余标记为"可删除候选"，仍须人工确认。

## 7. 数据库表设计

见 [数据库设计.md](数据库设计.md)。核心表：

- `files` — 文件索引（路径、大小、时间、哈希、domain、ftype、temp、confidence）
- `tags` / `file_tags` — 标签定义与多对多关联
- `plans` / `plan_items` — 迁移计划单与明细（源/目标路径、动作、状态）
- `op_logs` — 操作日志（用于回滚）
- `scan_state` — 扫描状态（增量游标）

## 8. 安全执行流程

```
用户确认计划（Web 二次确认 + confirm=true）
    ↓
1. 复制：src → dst.tmp（保留源文件）
    ↓
2. 校验：size + SHA-256 一致
    ↓
3. 删除：仅当校验通过，删除 src（移入回收站目录，不物理删除）
    ↓
4. 记录：写入 op_logs（含 src/dst/hash/time）
    ↓
回滚：根据 op_logs 反向恢复
```

**绝不直接 mv**：跨盘 mv 在 btrfs 上是 copy+delete，中途失败会丢数据。

## 9. 备份策略

| 数据类型 | 策略 |
|---|---|
| 个人 + 工作（不可再生） | 同步到另一块盘 + 外置盘/云端离线副本 |
| 音乐/影视/电子书（可再生） | 单份即可，不浪费空间备份 |
| 配置文件 + 索引库 | 定期打包备份；`data/` 目录含认证密钥，注意访问权限 |

具体目标路径由用户在 `config.yaml` 的 `backup` 段自行指定。

## 10. 分阶段开发计划

| 阶段 | 内容 | 验收 |
|---|---|---|
| P0 | 只读扫描 + 索引 | 能扫完配置的目录，索引入库，性能可接受 |
| P1 | 规则分类 + 重复报告 | 分类准确率抽样 > 95%，重复组正确 |
| P2 | 认证 + Web 控制台 + 手动执行 | 未登录不可操作；能预览计划、确认、执行可回滚 |
| P3 | 热备份 + 冷同步 | rsync 定时备份，校验通过 |
| P4 | 模型兜底 | 训练 fastText，低置信度件自动归类 |

## 11. 性能考虑

- 十万文件 stat 采集：预计 2-5 分钟（视磁盘），增量扫描只处理变更文件
- 三级哈希：一级过滤后通常只剩 5%-10% 进入二级，最终全量哈希 < 1%
- SQLite 索引：`path`、`size`、`mtime`、`ftype`、`domain`、`temp`
- Web 查询分页并设上限，避免一次加载全部记录
- 并发数可在配置中调整，避免影响 NAS 正常服务

## 12. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 单盘无 RAID，故障全丢 | 关键数据双份、离线备份、启用快照 |
| 自动移动误判 | 默认 dry-run、人工确认、每步可回滚 |
| Web 暴露导致恶意操作 | 强制认证、限流、非 root 运行、只绑内网、危险操作二次确认 |
| 扫描期间文件变化 | 记录扫描时间点，变更后增量重扫 |
| 哈希计算占用 CPU | 限制并发数、低峰时段运行、可配置 |
| 路径配置错误扫错目录 | 只读挂载 + config 路径校验 + 扫描结果抽样核对 |
