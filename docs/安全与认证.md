# 安全与认证

本项目会读取整个 NAS 的文件索引，并被授权执行**移动、删除、回滚**操作。因此安全不是可选项。本文说明已实现的防护、部署者必须做的事，以及已知边界。

## 一、威胁模型

| 风险 | 本项目的应对 |
|---|---|
| 局域网任意人打开网页就能移动/删除文件 | 全站 API 强制登录，无匿名读写接口 |
| 默认弱口令被扫爆 | 首次启动生成 20 位随机密码；无硬编码默认密码 |
| 密码数据库泄露后直接还原密码 | PBKDF2-HMAC-SHA256 + 每用户随机盐 + 21 万次迭代，不存明文 |
| 抓包重放、伪造登录态 | HMAC-SHA256 签名 Token，含签发时间与过期时间 |
| 暴力破解 | 按 IP 计数，连续失败 5 次后指数冷却，最长锁定 1 小时 |
| 猜密码时通过响应时间侧信道 | 所有敏感比较使用 `hmac.compare_digest` 常量时间比较 |
| 误触"执行"/"回滚" | 危险接口要求显式 `confirm=true`，前端再做一次确认弹窗 |
| XSS / 点击劫持 / 嗅探 | 文件路径输出做 HTML 转义；`X-Frame-Options: DENY`、`nosniff`、禁用缓存 |
| Token 被浏览器长期留在公共设备 | Token 存于 `sessionStorage`，关闭标签页即失效 |
| 改密后旧会话仍可操作 | 改密时轮换签名密钥，所有旧 Token 立即失效 |
| API 结构被探测 | 生产默认关闭 `/docs`、`/openapi.json`（设 `NAS_ORGANIZER_DOCS=1` 才开启） |

## 二、首次启动如何登录

1. 容器首次启动时，控制台会打印：

```
============================================================
[安全] 首次启动，已生成随机管理员密码： Xx7#kP2!...
[安全] 同时保存到 /app/data/INITIAL_PASSWORD.txt
[安全] 请登录后立即在「安全设置」中修改密码。
============================================================
```

2. 查看方式：

```bash
docker logs nas-organizer 2>&1 | grep '初始\|随机管理员密码'
docker exec nas-organizer cat /app/data/INITIAL_PASSWORD.txt
```

3. 浏览器打开 `http://NAS的IP:8765`，输入该密码登录。

4. **登录后第一件事**：右上角「安全设置」→ 输入当前密码与新密码 → 确认修改。修改成功后 `INITIAL_PASSWORD.txt` 会被自动删除，所有旧会话失效。

> 也可用环境变量 `NAS_ORGANIZER_ADMIN_PASSWORD` 预设**首次**密码，但**不推荐长期使用**：环境变量可能出现在 `docker inspect`、进程列表和编排文件中。该变量只在尚无 `data/auth.yaml` 时生效；一旦密码被持久化（含后续改密），环境变量即不再生效，重启也不会覆盖你改过的密码。建议首次启动成功后就从部署配置中移除该变量。

## 三、密码存储与 Token 机制

### 密码哈希

格式为 `pbkdf2_sha256$轮数$盐$哈希`，保存在 `data/auth.yaml`（文件权限 600）：

```
pbkdf2_sha256$210000$c29tZXNhbHR...$9f3a...
```

- 盐为 16 字节 CSPRNG 随机数，每个实例不同，无法用彩虹表
- 迭代次数 210000，兼顾安全性与 NAS 的低功耗 CPU；若硬件允许，可在 `auth.py` 中调高
- 校验全程常量时间比较，避免通过响应时长逐字符猜解

### Token

```
base64url(payload).base64url(HMAC-SHA256(secret, payload))
```

- `payload` 含用户名、签发时间、过期时间、随机 nonce
- `secret` 为 32 字节随机值，持久化在 `data/.auth_secret`（权限 600）
- 默认有效期 8 小时，可在 `config.yaml` 的 `auth.token_ttl_seconds` 调整
- 退出登录会将当前 Token 加入内存吊销表；容器重启后吊销表清空，需重新登录（属预期行为）

### 登录限流

- 同一 IP 连续失败 5 次后开始锁定，初始 30 秒，每多失败一次翻倍，上限 1 小时
- 距上次失败超过 10 分钟自动重置计数
- 失败事件写入容器日志：`[安全] 登录失败 IP=... 连续失败 N 次`

## 四、部署安全清单（务必逐项确认）

### 1. 绝对不要把 8765 端口映射到公网

这是最重要的一条。`docker-compose.yml` 中端口应绑定到内网地址：

```yaml
ports:
  - "192.168.1.100:8765:8765"     # 只绑 NAS 的内网 IP
  # 不要写成 - "8765:8765"（会监听 0.0.0.0 所有网卡）
```

如果必须远程访问，正确做法是：内网绑定 + VPN（WireGuard/Tailscale）或反向代理 + HTTPS + 额外一层认证。

### 2. 不要用 root 权限运行容器进程

镜像内置 `app` 用户（UID/GID 可通过 `PUID`/`PGID` 调整），entrypoint 会自动降权。只有初始化目录权限阶段使用 root。

### 3. 只挂载必要的目录，扫描目录严格只读

```yaml
volumes:
  - /你的/共享文件夹:/scan/data:ro     # 扫描：只读
  - /你的/整理目标:/write/target:rw    # 写入：仅此一处可写
```

不要把 NAS 根目录 `/` 或整个 `/volume1` 以 `rw` 挂进容器。

### 4. 保护持久化数据目录

`config/`、`data/`、`logs/` 应放在宿主机仅管理员可访问的目录。`data/` 内含密码哈希、Token 密钥、SQLite 索引，不要共享或提交 Git（已在 `.gitignore` 中排除）。

### 5. 防火墙

在 NAS 防火墙中只允许可信内网段访问 8765 端口。

### 6. 定期备份索引库

```bash
cp /volume1/docker/nas-organizer/data/nas_organizer.db \
   /volume1/docker/nas-organizer/data/nas_organizer.db.bak
```

索引库损坏不会丢原始文件，但重建需要重新全量扫描。

## 五、已知边界与注意事项

1. **限流是进程内内存计数**：单实例有效。多副本部署需改用外部存储（Redis）做共享计数——本项目定位是单机 NAS，不计划支持多副本。
2. **反向代理后的 IP**：默认取直连地址作为限流键。若置于反代之后，请确保在受控网络中，不要伪造 `X-Forwarded-For`。
3. **Token 无法跨重启保留**：重启后需重新登录，这是安全设计而非故障。
4. **认证不等于文件系统隔离**：容器进程的写权限由挂载点决定。请务必按最小权限原则配置 `rw` 目录。
5. **本工具不会删除源文件，除非你明确执行了计划**：`scan/classify/dedupe/plan` 全部只读；`execute` 也采用"先复制到目标、校验通过再删源"的策略。
6. **HTTPS**：容器本身只提供 HTTP。若 NAS 与访问端之间经过不可信网络，必须自行配置反代 TLS。

## 六、安全事件响应

如果发现异常登录或可疑操作：

1. 立即修改管理员密码（会自动踢掉所有会话）
2. 查看操作日志：`docker exec nas-organizer cat /app/logs/operations.log`（若启用）
3. 检查 `op_logs` 表：`sqlite3 data/nas_organizer.db "SELECT * FROM op_logs ORDER BY id DESC LIMIT 50;"`
4. 需要时用「操作」页的回滚功能撤销最近的批量移动
5. 删除 `data/.auth_secret` 并重启，可强制轮换 Token 签名密钥
