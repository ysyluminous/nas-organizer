# 案例：绿联 NAS 现状诊断（作者真实环境）

> **说明**：本文是项目作者在 2026-11-11 对自己 NAS 的一次真实摸底，仅作为"如何用本项目做体检与规划"的示例。
> 你的设备品牌、盘符、目录结构几乎肯定不同，请勿照抄路径。安装与路径配置请回到 [安装指南](安装指南.md) 和 [挂载配置指南](挂载配置指南.md)。

## 一、设备与容量现状

设备：绿联 NAS（mingzhang，UGLink 地址 `mingzhang.cn75.ug.link`），5 块盘，系统内存 8 GB（当时使用率 15.31%）。

| 卷 | 容量 | 已用率 | 剩余 | 当时定位 |
|---|---|---|---|---|
| volume1 / 8T1 | 7.26 TiB | 97.0% | 0.22 TiB | 冷数据归档 |
| volume2 / 16t1 | 14.54 TiB | 98.1% | 0.28 TiB | 冷数据归档（最大混乱源） |
| volume3 / 8t2 | 7.26 TiB | 95.5% | 0.33 TiB | 冷数据归档 |
| volume4 / 1T SSD | 0.89 TiB | 45.2% | 0.49 TiB | 热数据 / Docker |
| volume5 / 16t2 | 14.54 TiB | 42.3% | 8.39 TiB | 温数据主盘 |

**关键风险：5 个存储池全部是 basic 单盘，无 RAID 冗余。** 任何一块盘故障，该盘数据即不可恢复。这直接决定了工具必须默认 dry-run、写操作走"复制→校验→删除"并保留回滚日志。

## 三、当时给出的分层方案（思路可复用）

三条线拆开：**磁盘只管温度、目录只管归属、文件名只管类型**。

| 层级 | 载体 | 放什么 |
|---|---|---|
| 热数据 | 1T SSD | 当前项目、近期文档、常用证件、Docker 应用数据 |
| 温数据 | 16t2（8.39 TiB 可用） | 日常主库：个人 / 生活 / 工作 三类，下面再分 音乐 / 视频 / 图书 / 文档 / 图片 |
| 冷数据 | 8T1 / 16t1 / 8t2 | 近满盘只进不出，按 `归档-个人`、`归档-资源`、`归档-影视` 原地归类，不搬大块头 |

目标目录树示例：

```
volume4/                # 热
  ├─ 热-工作/
  ├─ 热-个人/
  └─ docker/

volume5/                # 温（日常主库）
  ├─ 个人/  音乐/ 视频/ 图书/ 文档/ 图片/
  ├─ 生活/  影视/ 音乐/ 照片/
  ├─ 工作/  项目/ 文档/ 参考资料/
  └─ 待删除/

volume1/2/3/            # 冷（归档，只进不出）
  ├─ 归档-个人/
  ├─ 归档-资源/
  ├─ 归档-工作/
  └─ 归档-影视/
```

## 四、执行顺序建议

1. **先减法**：清回收站、`待删除/`、`_gsdata_` 日志
2. **再去重**：对 `16t1/待整理` 先按大小+文件名粗筛，再哈希确认
3. **后归类**：确认保留的文件按目录树搬移；SSD 只留热层，冷盘只进不出
4. **安全兜底**：个人/工作在别处留一份副本；启用快照防误删

## 五、这个案例如何映射到本项目

| 案例中的发现 | 本项目对应能力 |
|---|---|
| 三个盘 95%~98% 满 | 温度层判定：mtime/atime + 所在卷 → 冷 |
| 12 万文件待整理目录 | 增量索引 + 三级哈希漏斗查重 |
| 电影/音乐/电子书散落多盘 | 路径规则 + 扩展名 → 归属域 × 文件类型 |
| 无 RAID 单盘 | dry-run + 复制校验删除 + 回滚日志 |
| 想按个人/工作/生活重组 | `domain_rules.yaml` 关键词与路径规则 |
