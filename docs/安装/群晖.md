# 群晖 Synology 安装指南

适用：DSM 7.x（Container Manager）、DSM 6.x（Docker 套件）。支持 x86 与部分 ARM 机型。

## 1. 前置准备

1. DSM 控制面板 → **终端机和 SNMP** → 勾选 **启动 SSH 功能**（用于查 UID 和排错）
2. 控制面板 → **共享文件夹** → 确认已有存放数据的共享文件夹（例如 `docker`、`media`）
3. 用 SSH 工具（PuTTY / Windows Terminal）登录 NAS

## 2. 确认真实路径与权限

```bash
# 查看卷和共享文件夹路径
df -h | grep volume
ls -ld /volume1/*

# 查看你的账号 UID/GID（记下 uid= 和 gid= 后的数字）
id 你的用户名
# 例：uid=1026(admin) gid=100(users) → .env 写 PUID=1026 PGID=100
```

群晖共享文件夹通常位于 `/volume1/文件夹名`，多卷时为 `/volume2/...`。

## 3. 创建项目目录并上传代码

```bash
mkdir -p /volume1/docker/nas-organizer/{config,data,logs}
cd /volume1/docker/nas-organizer

# 方式 A：git clone（NAS 已装 Git）
git clone https://github.com/ysyluminous/nas-organizer.git .

# 方式 B：用 File Station 上传仓库 zip 后在此解压
```

准备配置：

```bash
cp .env.example .env
cp config/config.example.yaml config/config.yaml
```

编辑 `.env`（可用 `vi`，或用 File Station 文本编辑器）：

```env
LISTEN_IP=192.168.1.100        # 改成 NAS 内网 IP；只本机访问可用 127.0.0.1
WEB_PORT=8765
PUID=1026                      # 第 2 步查到的 uid
PGID=100                       # 第 2 步查到的 gid
SCAN_1=/volume1/media          # 改成你的共享文件夹
WRITE_TARGET=/volume1/docker/nas-organizer-target   # 专门建一个空目录
```

编辑 `config/config.yaml`：

```yaml
volumes:
  - name: media1
    path: /scan/media1          # 容器内路径，与 compose 右侧一致
    role: warm
write_targets:
  - name: target
    path: /write/target
    writable: true
```

给应用数据目录授权（DSM 7 的 Container Manager 用户可能需要）：

```bash
chown -R 1026:100 /volume1/docker/nas-organizer
```

## 4. 启动容器

**方式 A：SSH 命令行（推荐，兼容性最好）**

```bash
cd /volume1/docker/nas-organizer
docker compose up -d --build
docker logs -f nas-organizer
```

DSM 6 老版本若只有 `docker-compose` 而非插件：

```bash
docker-compose up -d --build
```

**方式 B：Container Manager 图形界面**

1. 打开 **Container Manager** → **项目** → **新增**
2. 项目名称填 `nas-organizer`，路径选择 `/volume1/docker/nas-organizer`
3. 来源选择 **使用现有的 docker-compose.yml**
4. 下一步 → 完成，等待构建并启动

> 图形界面构建失败时，改用方式 A。DSM 对 compose 文件中的 `build` 支持因版本而异。

## 5. 首次登录

日志中出现：

```
[安全] 首次启动，已生成随机管理员密码： Xxxx...
```

浏览器打开 `http://NAS的IP:8765`，输入密码登录，然后立即到「安全设置」修改密码。

若 `LISTEN_IP=127.0.0.1` 导致打不开，改成 NAS 内网 IP 后重启容器，或用 SSH 隧道：

```bash
ssh -L 8765:127.0.0.1:8765 你的用户名@NAS的IP
# 本机浏览器访问 http://127.0.0.1:8765
```

## 6. 群晖专属注意事项

- **不要**把整个 `/volume1` 以读写方式挂进容器，只挂具体共享文件夹
- DSM 会在文件夹里生成 `@eaDir` 缩略图目录，配置中已默认排除，无需处理
- 群晖的 `users` 组 GID 通常是 100，个人用户 UID 从 1026 起；请以 `id` 命令结果为准
- 若共享文件夹启用了 Windows ACL，`docker` 用户可能仍无法写入，建议在 DSM 中给该账号显式授予读写权限
- 建议开启 DSM 的**快照计划**，对存放个人/工作数据的共享文件夹做定期快照

## 7. 常见问题

| 现象 | 解决 |
|---|---|
| 容器反复重启 | `docker logs nas-organizer` 看错误；多数是路径不存在或权限不足 |
| 扫描 0 文件 | 检查 `config.yaml` 是否写成 `/scan/media1` 而非 `/volume1/media` |
| `Permission denied` | 重新用 `id` 核对 UID/GID，并在 DSM 中确认该账号对共享文件夹有读权限 |
| Container Manager 里看不到容器 | 用 SSH 执行 `docker ps -a` 确认；有时界面缓存需刷新 |
| 端口被占用 | 修改 `.env` 的 `WEB_PORT`，如 8877 |
