## 1. 前置条件

- 任意支持 Docker 的 NAS 或 x86 / ARM64 主机（群晖、威联通、铁威马、飞牛、绿联、Linux 等）
- Docker 与 Docker Compose 可用
- 至少 1 GB 可用内存（索引十万级文件时建议 2 GB）
- SSH 访问（用于查 UID/GID 和排错，强烈建议开启）

## 2. 目录准备

在 NAS 上创建一个专门目录，例如：

```
/你的存储池/docker/nas-organizer/
├── docker-compose.yml       # 仓库根目录复制
├── .env                     # 由 .env.example 复制并修改
├── config/                  # 仓库 config/ 目录
│   ├── config.yaml          # 由 config.example.yaml 复制并修改
│   ├── type_rules.yaml
│   ├── domain_rules.yaml
│   └── temperature_rules.yaml
├── data/                    # 空目录，应用自动建库与认证文件
└── logs/                    # 空目录
```

## 3. 两个必须改的文件

### 3.1 `.env` —— 告诉 Docker 读哪里

```env
LISTEN_IP=192.168.1.100      # NAS 内网 IP；只本机访问用 127.0.0.1
WEB_PORT=8765
PUID=1000                    # 用 `id 用户名` 查到的 uid
PGID=100                     # 用 `id 用户名` 查到的 gid
SCAN_1=/你的/共享文件夹        # 宿主机绝对路径
WRITE_TARGET=/你的/整理目标    # 专门建的空目录
```

### 3.2 `config/config.yaml` —— 告诉程序在容器里读哪里

```yaml
volumes:
  - name: media1
    path: /scan/media1        # 与 docker-compose.yml 右侧路径一致
    role: warm
write_targets:
  - name: target
    path: /write/target
    writable: true
```

> 最常见的错误：把宿主机路径写进 `config.yaml`。容器内看不到宿主机路径，会导致扫描 0 文件。

## 4. 启动

```bash
cd /你的存储池/docker/nas-organizer
docker compose up -d --build
docker logs -f nas-organizer
```

首次启动会打印随机管理员密码。也可用：

```bash
docker exec nas-organizer cat /app/data/INITIAL_PASSWORD.txt
```

## 5. 首次使用流程

1. 浏览器访问 `http://NAS的IP:8765`，输入随机密码登录
2. 立即到「安全设置」修改密码（旧会话全部失效）
3. 「操作」页 → 扫描建索引
4. 「操作」页 → 重新分类、重复检测
5. 「概览」页核对统计；分类不准就改 `config/domain_rules.yaml` 后重跑
6. 「迁移计划」→ 生成计划 → 查看明细 → 确认无误后再点"执行"
7. 出问题到「操作」页回滚，或 CLI 执行 `rollback`

前三步（扫描/分类/查重）全是只读操作，可放心跑。

## 6. 备份配置（可选）

在 `config.yaml` 中：

```yaml
backup:
  hot:
    enabled: true
    source: /write/target
    target: /backup            # 需在 docker-compose.yml 中挂载 BACKUP_TARGET 到 /backup:rw
    schedule: "0 2 * * *"
    max_age_days: 90
  cold:
    enabled: true
    verify_hash: true
```

## 7. 安全清单

- [ ] 端口只绑内网 IP，未映射公网
- [ ] 扫描目录全部 `:ro`，只有 `/write/*` 是 `:rw`
- [ ] 未把 NAS 根目录或整个卷以读写方式挂进容器
- [ ] 已用 `id` 核对 PUID/PGID
- [ ] `docker exec nas-organizer id` 确认不是 root
- [ ] 首次登录后已修改随机密码
- [ ] `data/` 目录未共享、未提交 Git
- [ ] 重要数据有另一份离线备份或快照

完整说明见 [安全与认证](安全与认证.md)。

## 8. 常见问题

| 现象 | 解决 |
|---|---|
| 扫描 0 文件 | 检查 `config.yaml` 是否用了容器内路径 `/scan/...` |
| 报 `Permission denied` | 重新用 `id` 核对 PUID/PGID，确认该账号对共享文件夹有读权限 |
| 打不开 Web 页面 | `LISTEN_IP` 若为 `127.0.0.1` 只能用 SSH 隧道；改为 NAS 内网 IP 后重启容器 |
| 容器反复重启 | `docker logs nas-organizer` 看具体错误，常见为路径不存在 |
| 忘记密码 | 删除 `data/auth.yaml` 后重启容器，会重新生成随机密码（旧 Token 同时失效） |
| 索引库损坏 | 删除 `data/nas_organizer.db` 后重新扫描；原始文件不受影响 |
