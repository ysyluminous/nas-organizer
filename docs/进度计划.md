## 1. ROI 排序方法

```
ROI = 价值(v) × 差距(g) × 通用性(u) ÷ 成本(c)
  v：对用户实际价值（1–5）
  g：同类领先、我们缺失的程度（1–5；我们已具备的 g 低）
  u：跨品牌通用系数（0.5 垂类 / 1.0 一般 / 1.5 全平台通用）
  c：实现成本（1–5，越大越难）
```

分级：**S ≥ 15**（立刻做）· **A 8–14.9**（本周做）· **B 4–7.9**（有余力做）· **C < 4**（观察或明确不做）。

统计：S 13 项 · A 11 项 · B 12 项 · C 6 项 = **42 项同类优点全量覆盖**（含 1 项已具备、4 项明确不做）。

## 5. 每日提交与回滚约定


1. **每天一个 commit**，只做当天 ROI 最高的事；不跨天混提，方便按天回滚
2. **最小化改动**：新增能力优先走"新文件 + 配置开关"，不改 `scanner/classifier/executor` 主链路；必须改时用开关包裹，默认关闭
3. **不动存量**：已有测试全部保持通过；`config.yaml` 新增字段必须有默认值
4. **安全不退化**：任何新接口上线前先跑认证集成测试；MCP 写工具必须带 confirm
5. **文档同步**：每天提交同时更新 README 或对应 docs，避免代码跑在文档前面
6. **不本地编译**：本机验证限于单元测试 + CLI 冒烟 + `docker compose config`；真机联调放在部署后
