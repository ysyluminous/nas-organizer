# 挂载配置指南

这套模板刻意**不写死任何品牌或盘符路径**。每个人的 NAS 目录结构都不同，你只需要理解三类挂载的职责，然后填自己的路径。

## 一、三类挂载，职责必须分开

| 类别 | 容器内路径 | 权限 | 用途 | 能不能省 |
|---|---|---|---|---|
| A. 扫描源 | `/scan/*` | `:ro` 只读 | 扫描、分类、查重——这些操作只读文件，绝不能改文件 | 至少一个 |
| B. 写入目标 | `/write/*` | `:rw` 读写 | 执行迁移计划、热数据备份时真正写入 | 只做体检可先不挂 |
| C. 应用数据 | `/app/config`、`/app/data`、`/app/logs` | 配置只读，其余读写 | 规则配置、SQLite 索引、认证密钥、日志 | 不能省 |

核心原则：**扫描引擎永远看不到写权限**。即使 Web 控制台被攻破，攻击者也只能读到索引（文件名、大小），无法凭容器权限改动你的扫描源——除非你主动挂了 B 类目录。

## 二、路径的对应关系（最容易错的地方）

一个路径要出现三次，且每次写法不同：

```
① 宿主机路径     /volume1/共享文件夹        ← 写在 .env 的 SCAN_1
                        ↓ docker-compose 挂载
② 容器内路径     /scan/media1               ← 写在 docker-compose.yml 右侧
                        ↓ 配置引用
③ config.yaml    volumes[].path: /scan/media1
```

三者必须一致：`.env` 决定"读哪里"，compose 决定"挂到容器哪个位置"，`config.yaml` 告诉程序"去容器里哪个位置扫描"。

示例 `.env`：

```env
SCAN_1=/volume1/共享文件夹
WRITE_TARGET=/volume2/整理目标
PUID=1026
PGID=100
```

对应 `docker-compose.yml`：

```yaml
- "${SCAN_1}:/scan/media1:ro"
- "${WRITE_TARGET}:/write/target:rw"
```

对应 `config/config.yaml`：

```yaml
volumes:
  - name: media1        # 自定义显示名，统计里显示
    path: /scan/media1  # 必须与 compose 右侧一致
    role: cold          # hot / warm / cold，仅作标记
write_targets:
  - name: target
    path: /write/target
    writable: true
```

> 常见错误：把宿主机路径（如 `/volume1/xxx`）写进 `config.yaml`。容器里没有这个路径，扫描会返回 0 个文件。

## 三、增加更多盘

`.env` 中追加变量：

```env
SCAN_1=/volume1/照片
SCAN_2=/volume2/视频
SCAN_3=/volume3/文档
```

`docker-compose.yml` 中取消对应行的注释：

```yaml
- "${SCAN_1}:/scan/media1:ro"
- "${SCAN_2}:/scan/media2:ro"   # 取消注释
- "${SCAN_3}:/scan/media3:ro"   # 取消注释
```

`config/config.yaml` 中追加对应的 volume 条目，路径填 `/scan/media2`、`/scan/media3`。

没有更多盘就删掉多余的行，保持配置干净。

## 四、PUID / PGID 是什么，为什么必须配

Docker 容器内的进程用户与 NAS 宿主机的用户通过 UID/GID 数字对应。如果容器内用户（默认 1000）对宿主机共享文件夹没有读/写权限，就会出现：

- 扫描结果为空（读不到）
- 执行迁移时报 `Permission denied`
- Web 控制台日志里出现 `PermissionError`

**查看宿主机 UID/GID：**

| 环境 | 方法 |
|---|---|
| 群晖 SSH | `id 你的用户名`，看 `uid=` 和 `gid=` |
| 威联通 SSH | `id 你的用户名` |
| 飞牛 SSH | `id 你的用户名` |
| 绿联 SSH | `id 你的用户名` |
| 铁威马 SSH | `id 你的用户名` |
| Linux 通用 | `id $USER` |
| Windows + Docker Desktop | 通常 `PUID=1000 PGID=1000`；WSL2 挂载可用 `id` 确认 |

把查到的数字填进 `.env`：

```env
PUID=1026
PGID=100
```

容器启动时 `entrypoint.sh` 会把应用进程切换到这个 UID/GID。注意：

- 这个用户必须对 A 类目录有**读**权限，对 B 类目录有**写**权限
- 不想解决权限问题时，可临时对特定目录 `chmod -R a+rX /路径`（读）来排查是否是权限问题
- 不推荐直接 `chmod 777`，应优先用 PUID/PGID 正确映射

**验证当前容器用户：**

```bash
docker exec nas-organizer id
docker exec nas-organizer ls -ld /scan/media1 /write/target
```

## 五、只做"体检"的最小配置

如果你暂时只想要分类统计和查重报告，不打算执行任何迁移，可以用最保守的挂载：

```yaml
volumes:
  - "/你的/共享文件夹:/scan/media1:ro"
  - ./config:/app/config:ro
  - ./data:/app/data:rw
  - ./logs:/app/logs:rw
```

即：只挂 A 类和 C 类，不挂 B 类。此时容器完全没有写文件的路径，安全等级最高。跑 `scan → classify → dedupe`，看 Web 控制台报告即可。确认要执行迁移时，再加上 B 类挂载并重启容器。

## 六、各品牌路径速查（详细步骤见安装文档）

| 品牌 | 共享文件夹常见实际路径 |
|---|---|
| 群晖 Synology | `/volume1/文件夹名`（多卷为 `/volume2/...`） |
| 威联通 QNAP | `/share/文件夹名` |
| 飞牛 fnOS | `/vol1/1000/文件夹名` 或 `/vol1/文件夹名` |
| 绿联 UGREEN | `/volume1/...` 到 `/volume5/...` |
| 铁威马 TerraMaster | `/Volume1/文件夹名`（注意大写 V） |
| Linux / Debian | `/mnt/...`、`/srv/...` 或任意挂载点 |
| Windows | `C:\path`（在 compose 中写 `/c/path` 或 `C:/path`） |

**如何确认自己的真实路径：**

```bash
# 在 NAS 的 SSH 中
ls /volume*        # 群晖/绿联
ls /share          # 威联通
df -h              # 通用：看挂载点
docker run --rm -v /源路径:/test alpine ls /test   # 验证路径存在且可读
```

## 七、路径中含空格或特殊字符

- `.env` 中含空格的路径要用引号包裹：`SCAN_1="/share/My Media"`
- `docker-compose.yml` 中 `volumes` 的每一项整体加引号：`- "${SCAN_1}:/scan/media1:ro"`
- 尽量避免中文、空格和特殊符号作为共享文件夹名，某些 NAS 的 Docker 实现处理不佳

## 八、常见问题排查

| 现象 | 原因 | 解决 |
|---|---|---|
| 扫描 0 个文件 | `config.yaml` 里写的是宿主机路径而非容器内路径 | 改成 `/scan/...` |
| 报 `Permission denied` | PUID/PGID 与该目录属主不一致 | 用 `id` 查正确 UID/GID 并更新 `.env` |
| 容器反复重启 | 挂载的宿主机路径不存在 | 检查 `.env` 路径；Docker 会自动创建空目录，导致误以为是空盘 |
| 端口访问不到 | 只绑了 `127.0.0.1` | 改成 NAS 内网 IP，或经 SSH 隧道/反代访问 |
| 看不懂改了哪些配置 | `.env` 是唯一需要改的路径来源 | 不要同时改 compose 里的默认值和 `.env` |
| 备份任务写不进去 | B 类目录没挂或权限不足 | 挂载 `/backup` 并确认 PUID 有写权限 |

## 九、安全性自检清单

```bash
# 1. 扫描目录是否真的只读？
docker exec nas-organizer touch /scan/media1/__test__
# 预期：Read-only file system（如果成功创建了，说明漏了 :ro，立即删除该文件）

# 2. 端口是否只绑内网？
docker ps --format '{{.Ports}}' | grep 8765
# 预期：192.168.x.x:8765 或 127.0.0.1:8765；不应是 0.0.0.0:8765

# 3. 应用是否非 root 运行？
docker exec nas-organizer id
# 预期：uid=你的PUID(...) 而不是 uid=0(root)
```
